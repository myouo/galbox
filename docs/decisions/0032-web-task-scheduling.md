# ADR0032：Web预算续跑、主线程响应与程序索引

状态：W1-01实施中，服务于用户“在Web实际游玩GalGame”的最终目标。对照v0.6第3.3、4.3–4.5、6.2–6.7、10.4与11.5节；本轮不重开语言选择、不引入Rust/WASM或第二解释器。

1. Web异步分为I/O异步、合作式主线程让出与Worker并行。现有网络/媒体/IndexedDB的Promise不自动保证渲染机会；queueMicrotask连续续跑会耗尽微任务队列后才交还事件循环，不满足长计算时真正让出浏览器的目标。
2. Web adapter以实例拥有的MessageChannel任务调度预算续跑；不支持时退到setTimeout。Core仍同步，Coordinator保持同一current逻辑轮次，外部输入/回调只排队，预算不是新保存切点。不得重新提交上一个点击。端口按首次调度创建，失败的Player构造不分配端口；dispose取消自身待调度工作，候选等待明确失败，不影响其他Player。
3. 启动候选的预算续跑同样真正让出，并在每片前检查请求代次与dispose；原100000操作上限不放宽。构造/JSON解析/单次同步插件自身仍可能长，不能把此项包装成已提供Worker或模块化加载。
4. Player在已有逻辑轮次预算续跑时不额外积压rAF tick；活动时间在该轮完成后的下一次受理中结算。Coordinator不合并已受理的规范事件；真人输入/媒体事件仍在原轮结束后裁决，限时提示仍依prepared→active屏障。
5. Core为已链接的私有Program建立函数/指令/后继索引，替换执行时反复线性查找。索引增加O(指令数)引用表空间，构造/验证仍单独计时，不能把执行优化冒充零成本启动。地址/帧/返回/恢复规则不变；外部输入校验、完整snapshot和预算确定性保留。

验收：相同长程序的前后吞吐/主线程心跳、预算1/8/100相同snapshot、真实Player运行/启动让出、保存切点拒绝、旧事件/代次与销毁取消、无MessageChannel后备、自动/快进/媒体回归与独立包。图形释放按H3-02固定帧/finish控制实验独立归因；不把异步延后清理当性能优化。

原计划的按需资源/有限预取/LRU、Program模块加载、可恢复离线安装等尚未完成，单列任务，不因本调度器修复而声称全部Web异步能力齐备。
