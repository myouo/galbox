# ADR0033：可选择的资源加载策略与资源提交屏障

2026-10-27，W1-02，基线fe86769。用户明确要求多种策略，不预设所有设备/网络的唯一最佳答案。

1. 有限LoadingOptions由Schema生成与真实loadingPolicy工厂校验。eager（默认兼容旧行为）、demand（仅必需）、balanced（必需+有限直线前看）、chapter（作者声明函数到资源组）共用生产管理器。支持并发数、驻留字节和预取窗口；不根据不普遍可用的网络/内存提示静默改策略。
2. lazy策略需要已核验正式release事实；未检查内容的manifest事实不等于字节已验证。现有release目录预算/256目录上限不改解释；新增驻留预算单列，完整大作品目录/程序规模仍W1-03。字体、标题图及系统成就小图作为启动基础资源；章节/正文/UI/舞台/效果需求准备后才显示。
3. 分开下载/校验、设备准备、驻留与呈现引用。并发有界；同资产请求去重，预取不阻塞必需队列；预取失败不使剧情失败。使用期和准备期资源固定，LRU只淘汰无引用项；实例取消不关闭其他实例。实际RGBA/PCM/Blob/字体占用与下载缓冲都有界，不能用LRU突破提交时新旧资源共存预算。
4. Coordinator在稳定轮次和效果分发前调用中立准备端口，长等待不重入Core。准备中展示上一已提交视图、禁捕获/保存/持久flush/自动推进；Host回调继续排队。失败保留目标和效果、提供显式重试，不重新执行变量/RNG/历史确认。关闭取消准备；晚回调不能复活。该资源屏障暂不可序列化，不新增伪保存切点。
5. 激活候选的资源在持久提交之前准备并固定；代次过期取消，旧画面仍有效。准备成功再执行原head事务/Host接管；提交后故障沿原committed-pending恢复。图形呈现成功后释放上一视图引用，不在载入中销毁当前画面。
6. balanced只读取声明中的有限未来指令，不执行条件/插件/RNG，不越过未知控制流猜分支；chapter由作品显式声明分组、按活动调用栈选定，不把所有分支预取当免费性能。
7. 离线安装是独立W1-04能力。内存缓存/HTTP缓存/完整可恢复离线安装不能混同。先提供创建时策略选择；运行时切换、跨实例共享缓存及持久下载管理不在本有限集内。

验收包含真实慢HTTP首屏/请求量/驻留与淘汰对照、取消/迟到/校验失败/重试/保存拒绝/旧画面、读档跨策略/刷新、分支不猜测、字体/媒体/UI/鉴赏和独立tarball。按实测结果记录任何未完成支持，不以策略名宣称完成。

实测兼容调整：原stream取消反例依赖旧预载串行顺序；因此未显式配置时eager默认并发1，其余默认3。显式配置仍为1–8，并新增并发媒体逐租约归还反例，不改变完整性与所有权规则。

准备端口拿到Core只读冻结投影和独立效果DTO，失败的自定义准备器不得污染重试队列中的效果。回归用修改其收到的Task再失败的端口验证所有权隔离。
