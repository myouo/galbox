# ADR0031：受控状态视图与重复验证优化

状态：H3-01有限优化验收完成，证据见../evidence/h3-01/REPORT.md；用户本轮优先性能。沿TypeScript生产Core/协调器/Host/IndexedDB，不改变剧情、协议支持集、存档格式或暂停时钟，不删历史、不跳过外部校验。

基线测量：1000历史浏览器推进P95约37–203ms（配置不同），Core10000历史空闲tick约93ms；CPU记录显示JSON私有化/重复TextState验证、历史提交和PNG捕获成本。完整复跑场景见profile-runtime.mjs。

1. Core.view返回校验过且深冻结的只读视图，同一状态可复用。所有公开状态变更/预算续跑/回执/撤销/recipe使缓存失效；旧视图保持不变。capture仍给独立、完整校验的可写DTO，不与view/权威状态共享可变别名。
2. Core历史是只追加的封存记录，权威数组冻结后以新数组追加。历史来源变化时完整校验快照并建立历史只读副本；普通tick仅校验活动字段，再结合缓存历史的精确节点数、深度和JSON字符数检查原有总预算。仍保留10000条/100000节点/64层/4000000字符边界，不以缓存绕开全量存档/恢复校验。
3. 协调器/Player在一轮中复用视图；默认DOM渲染器消费已隔离只读对象，用户自定义renderer仍得到独立拷贝。脚本UI只保留其实际使用的ui/wait数据，避免把完整剧情历史再复制一次。
4. HistoryEntry/Record/Commit在各自外部边界只私有化和Schema验证一次，父Schema已验证的子记录只执行语义关联检查。仍检查完成正文、实际切点、唯一身份、容量、修订/authority/幂等回执；存储布局与原子提交不变。
5. 历史索引、文本签名和容量计数仅作用于私有受控数据；传给自定义Store的提交仍隔离，失败重试批次不变。已验证内部JSON可直接规范序列化，公共unknown入口仍做完整JSON边界检查。
6. 捕获保留所有计算样式，只合并完全相同的样式声明，不用样式白名单换速度。固定视口/相同逻辑切点的PNG像素对照和完整保存恢复必须通过。

验收：相同工作负载前后原始样本/CPU归因，Core预算与语义trace一致、视图冻结/旧引用/回执/失败/所有权负例；真实IndexedDB、历史回溯/保存刷新、图像像素、Canvas/WebGL及独立包。基准和规模矩阵是有限证据，不认证全部设备/无限历史；G7综合任务仍保留。
