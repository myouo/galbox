# ADR-0001：实施起点

状态：采纳为任务包默认；2026-10-24。未表示相应模块已经实现。

| 决定 | 理由 | 可重新评估的具体条件 |
| --- | --- | --- |
| 唯一 TS Core，WASM 按外围模块引入 | 当前目标为 Web 和第三方 TS SDK，未知解包不属于 Core | 新增无 JS 原生嵌入硬要求或有测量证据的计算收益 |
| 一个主库加显式子路径 | 降低初始发布/依赖管理成本，保留内部模块边界 | 独立发布/依赖隔离出现实际需求 |
| 初始单 Pixi 舞台 + DOM 正文 + React UI | 让对象/动画可统一调度与恢复 | 广泛实现前代表素材证明单 DOM 更合适；不双维护 |
| 单剧情流、并行表现任务 | 有限状态图可以保存恢复 | 真实作品出现不能有界表达的必要多控制流语义 |
| wire Schema 单源 | 减少类型/校验器漂移 | 不因开发便利撤销外部输入验证 |
| 工作 profile + 批次回执 | 让普通进度、重试和槽位捕获的关系明确 | 具体作品证明需要且能验收的合并策略 |
| 内部快照与原档交换格式分开 | 不让一个作品格式约束所有 Core 状态 | 不因来源相同而合并格式和语义责任 |
| M2 后立即独立消费者验证 | 提前发现公共 API 和文档无法完成接入 | 不延后到两作内容全部接完 |

后续 ADR 只记录改变公开语义、依赖边界、恢复协议或交付范围的实质决定。小实现选择可在任务证据中记一句，避免每次改动写一篇架构报告。
