# ADR0034：存储冷热分离与旧激活载荷回收

2026-10-27，W1-03A，基线92d3e18。W1-03为聚合任务，A完成不代表程序模块或大作品容量完成。

1. 先保持4M JSON字符命名空间总预算及现有Snapshot/备份格式，拆开每个slot和每个profile的history journal。常用profile/preferences/回执/head为热记录；普通提交不读写其他槽位图片/历史。不是只提高上限。
2. IndexedDB升级到版本2（同namespaces对象仓库）：字符串namespace键保留热记录和生成Schema的布局目录，冷记录用[namespace,kind,id]复合键。目录记录冷载荷字符量与slot摘要；未知布局/缺记录明确损坏拒绝。目录/相关冷记录在同一原子事务读写，全部验证在提交前完成；不在事务内等待网络、摘要或其他异步I/O。
3. 旧数据库版本连接收到versionchange关闭，旧SDK的open(version1)明确失败，避免双写。旧逻辑记录在第一次写事务按namespace原子迁移；失败保留旧记录，readonly可继续读取旧布局，旧档不丢失。
4. superseded activation改为有界结构的tombstone，仅保留id/sequence/明确superseded身份，不再复制旧快照。当前head与当前activation仍完整；旧ID始终拒绝接管，不能删除身份后复活。所有progress/save/import/backup/history回执保留原语义与幂等性，本轮不做时间过期清理。
5. 所有读写仍经过真实durable reducers与Schema/语义校验；分片只隔离本操作用不到的cold载荷，不能用空数据冒充读取成功。所需冷记录按目录加载，缺失/损坏拒绝；全量备份仍检查完整闭包及原1M字符预算。只读损坏不自动删除旧档。
6. MemoryStore继续使用同一纯事务函数与逻辑预算，旧激活瘦身同样适用。结构化布局不是可携带备份格式，浏览器迁移失败/终止/跨连接冲突必须实测。

验收：相同0/16/48槽位真实Core快照工作负载的前后读写量/时间；热操作不访问冷键，保存仅同写目标槽位/目录/回执；迁移事务abort不留半份，版本变化关闭旧连接；旧激活ID拒复活、幂等回执、备份与上一修订仍恢复，IndexedDB/刷新/两图形后端/独立包回归。

剩余：热记录中head/profile/回执仍整体处理，4M总预算/1M备份预算未取消；按记录进一步扩容与留存属W1-03C。程序分包须真正按执行依赖准备和验证恢复闭包，禁止把先下载全部再合并冒充懒加载，属W1-03B。
