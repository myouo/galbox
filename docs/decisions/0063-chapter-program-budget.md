# ADR0063：程序/文本目录与运行中数据分开计量

真实第一门首次完整降低（尚未精简重复style）测得279699节点、4373736 JSON字符、2492个正文切片。即使精简style与共享转换函数，整章程序也不适合与单个快照/消息共用100000节点上限。

Program和ProgramTextCatalog专用上限512000节点、8000000字符、64深度；protobuf预扫描和解码逻辑预算按调用方要求的类型选择，错误Envelope类型不能借机升级。Snapshot/Profile/扩展输入/通用JsonValue仍保持100000节点/4000000字符。此为有界整章载荷支持，不代表高级能力已支持按需代码模块，后者仍另验。

内部已验证Program的发布摘要与extras/flow闭包摘要使用对应程序预算；排序/摘要算法与已有短程序完全相同。不得把新上限套到外部任意JSON或存档。要求大原创程序真实Builder、protobuf、拆分绑定、发布验证与Core保存恢复；超过专用界限仍拒绝，旧普通JSON界限不变。

精简差分style后同章218021节点/3610054字符/247资产；合并序章会超过原256资产目录。Program资源与Release资源事实数组上限改为512，设备驻留/单图/解码/快照任务等预算不变。streamCatalog小目录保留原格式；超过原65536字符的目录用完整规范目录SHA256固定串，未放宽快照字段。旧可加载程序不改变签名，大目录此前不可加载，无旧档可被误接纳。
