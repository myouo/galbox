# Codex 执行与接续流程

## 1. 唯一状态来源

完整任务表为 docs/tasks.json。STATUS.md 只保存本轮目标、工作区差异、最新失败/证据和下一步。MILESTONES 定义门槛，ACCEPTANCE 定义验证；它们不复制任务完成状态。

任务 status 为 todo/in_progress/blocked/done；implementation 为 not_started/in_progress/complete；verification 为 not_run/in_progress/passed/failed/blocked。done 只有在实现 complete、规定验证 passed 且证据可定位时成立。任务包生成和文档语法检查不满足任何引擎任务。

## 2. 每次启动

检查适用规则、Git/文件事实和用户改动。读取 STATUS/tasks，定位上轮 task ID 和真实文件。环境已有已完成工程时做增量对齐，不重建。状态标 done 但代码/证据不支持时纠正状态并说明原因，不盲信旧记录。

没有可用的 Git HEAD 或存在未提交更改时，可记录工作树/相关文件摘要；不为了造证据替用户提交无关更改。一个任务开始前读关联契约和验收即可，不每轮通读全部历史研究。

## 3. 选择与实施

首轮 scope 为 M0–M2。续建优先未完在途任务，再按依赖图选择可执行项；某个浏览器验收阻塞时可以继续无此依赖的逻辑任务，但所属阶段不能因此标通过。N/F 只在有真实资料时推进相应证据任务。

为当前里程碑维护 docs/execplans/ACTIVE.md，列目标、任务、改动位置、验证和发现；简短到能直接执行。开始实现后按真实情况更新，不把计划写作代替实施。

实现一个能被当前消费者使用的完整行为。契约变化同时改 Schema/类型/运行校验/操作表/调用者和反例；内部命名和小型重构自行决定，重大语义变更记 ADR。公开能力只登记实际实现。

## 4. 验证与一次聚焦审查

运行相关检查并定位失败，不放宽语义以“过测试”。先看输入、期望、实现哪个错，再修对应项。对本轮真实风险做一次聚焦审查，解决发现后前进，不反复要求全面架构 review。

可以用子代理做独立审查或无共享写入的模块。共享协议、导出入口、任务表与最终整合由当前负责人维护，不能多个代理同时覆盖；只有实际可用工具时使用，提示词不假设代理功能必然存在。

## 5. 阻塞处理

记录阻塞分类、具体操作、已知原因、最小所需输入、可继续的任务。缺原档不阻塞通用模块；缺 Playwright/浏览器权限时不声称已跑真浏览器；只需外部发布授权时先完成可审查的本地包和验证。

不因每个可逆文件修改或常规实现选择询问。尊重已有授权和环境限制，不删除用户工作、扩大权限或绕过审批。涉及真正目标冲突且无法凭现有要求解决时，在完成其余有用工作后集中提出问题。

## 6. 更新与结束

完成一个任务后，在 docs/evidence/ 写实际结果，再更新 tasks.json 状态/证据引用；同步 STATUS 的当前摘要。记录还有哪项未测，明确首个可执行下一步。

本轮结束报告只需：任务 ID/行为；实际验证；运行方法；未完成和阻塞；精确接续入口。若上下文/时间限制中断，保留 in_progress/blocked 并写当前代码状态，不把“本轮结束”改成“项目完成”。

当 M0–M5 都完成而 N/F 仍缺资料时，交付真实的 SDK alpha 和精确缺失清单；不要凭空继续发明功能或宣布 M6 通过。
